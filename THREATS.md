# TrustVault threat register

This is a working threat register. Verification status reflects the automated tests currently in the repository; it is not a claim of independent security certification.

| Threat | Current mitigation | Verification status | Remaining work |
|---|---|---|---|
| Guessing a document ID (IDOR) | Metadata, content, download, and owner actions check current owner/grant state | HTTP tests cover private metadata isolation, admin content denial, Read-only content, denied download, and post-revocation denial | Add route-by-route tests for every method and role |
| Read permission used to download or edit | Content, download, and metadata update have separate checks | HTTP tests confirm Read can view but cannot download or edit; mutation test removes download guard and expects the authorization assertion to fail | Extend to every route and permission combination |
| Private metadata leakage | Listing filters to owned/granted documents; Public is explicit metadata discovery | HTTP test checks ungranted viewer and administrator do not see private document metadata | Test deleted docs, disabled accounts, and list-query edge cases |
| Expired/revoked grants | Every protected content request checks expiry and revocation | HTTP tests verify expired grants disappear from private listing and content is denied, and revoked grants block next requests | Test timezone edge cases, concurrent streams, and expiry during transfer |
| Unauthorized access requests | Requests limited to Public docs and non-owners; duplicate pending requests rejected | HTTP test covers public discovery, duplicate pending rejection, approval, and a later request after decision | Add self-request, private request, rejection and cross-owner request tests |
| Upload abuse | Size cap, extension/MIME/signature checks, generated storage keys outside public directory; multipart parser rejects malformed boundaries and duplicate fields | HTTP tests exercise valid TXT upload, malformed multipart, duplicate fields, multiple files, MIME mismatch, configured size limits, and NUL-containing TXT rejection | Add oversize, traversal filename, MIME mismatch, fuzzing, full format parsing, and malware scanning |
| Session theft/fixation and CSRF | Random session token stored as hash, HttpOnly/SameSite cookie, session rotation, CSRF token on mutations, idle and absolute expiry | HTTP tests cover CSRF denial, logout, idle and absolute session expiry, and invalidation after account disable | Idle and absolute expiry plus production Secure-cookie tests now pass; add more cookie, rotation, and proxy deployment tests |
| Login brute force | Generic login errors and in-process IP/account rate limiter | HTTP test confirms repeated failed attempts result in 429 | Use shared edge rate limiter for multi-instance deployment and test proxy IP handling |
| Audit modification | HMAC-SHA256 chained events; production key configured separately | HTTP tests verify chain consistency after normal and denied operations and detect a modified stored event | Runtime test now detects event modification; add truncation tests and externally immutable checkpoints |
| Administrator privilege escalation | Admin account endpoints check Administrator role; admin role alone does not grant document-content access | HTTP test checks administrator cannot access private document content without a grant and can use audit verification | Add full admin endpoint matrix and denied-event assertions |
| SQL injection and stored XSS | Prepared statements for user input and DOM textContent for displayed data | Code review only | Add payload tests, security scanning, and dependency/runtime review |
| Production Origin bypass | Mutating requests require exact configured Origin in production | Production-mode HTTP test confirms missing and wrong Origin are rejected, trusted Origin reaches authentication, and the session cookie is Secure/HttpOnly/SameSite=Strict | Verify behavior behind the actual production proxy and configured domain |

## Deployment blockers

Do not use this review build for confidential production documents until production Origin behavior is runtime-tested, upload handling receives independent review and malware scanning is considered, backups/restores and monitoring are configured, audit evidence is independently anchored, and an external security review is complete.
